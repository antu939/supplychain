D8

履约分配

当可用成品不能完全覆盖客户订单时，决定优先分给哪个客户、渠道或市场，何时交付，以及多少订单需要延期。

01

决策流

订单 + 可用库存 + 近期到货 + 客户优先级 → D8 → 最终分配与交付；实际发运 / 销售再反馈 D1，并形成真实收入与销售损失。
02

这个决策是做什么的

D8 决定“给谁”。

D8 位于决策链的最后一段。它把当前可用成品、短期到货、客户优先级、订单价值与市场限制放在一起，形成最终订单分配与交付承诺，并把真实销售和未满足需求反馈回下一轮决策。

03

输入与输出

输入
需求 / 订单读取客户订单、产品、数量和要求日期，明确客户现在真正需要多少货、什么时候需要。
D6 可用成品库存读取当前真正可以承诺给客户的成品数量，是 D8 最直接的硬约束。
D7 近期到货读取短期内还会到多少货、什么时候到，判断是否可以支持稍后的客户交付。
市场 / 客户读取客户等级、渠道、市场、服务承诺与优先级，确定供给不足时谁更应该优先保障。
资金与经济性 + 风险 / 合规读取订单价值、利润、信用边界和市场准入限制，避免把货分给经济上或合规上不可执行的订单。
输出
订单分配 / 承诺 / 延期订单 / 客户 × 产品 × 日 / 周 × 分配数量 × 发运日期 × 延期数量。写回：需求 / 订单；后续：销售、仓库和物流按承诺执行
实际发运 / 销售 / 服务结果订单 × 实际发运 / 交付 × 数量 × 收入 × 服务结果。写回：需求 / 订单；后续：反馈 D1 承诺与下一轮需求信息
实际收入 / 销售损失订单 / 市场 × 实际收入 / 销售损失 × 时间。写回：资金与经济性；后续：评价服务损失与供应链经济结果
实际动作：在供给不足时，正式决定各客户 / 渠道 / 市场获得多少成品、什么时候交付，以及哪些订单需要延期。
04

KPI：怎么算，有什么用

满足率

实际满足数量 ÷ 客户需求 / 订单数量

用途：看客户需求有多少被真正满足；下降时先看可用库存与近期到货，再继续追采购、生产、库存和物流环节。

客户准时足量交付率

准时且足量交付的到期订单 ÷ 全部到期订单

用途：看公司对客户交付承诺是否兑现；偏低时结合 D7 的预计到达以及 D5 / D6 状态定位原因。

延期 / 丢失销售

延期数量 = 到期未满足数量；丢失销售 = 最终取消或无法满足的数量

用途：看供给不足带来的客户与收入损失；持续上升时反馈 D1 承诺、D6 库存以及 D4 / D5 的供给策略。

05

例子、适合算法与重新运行条件

例子

当可用成品少于所有订单需求时：

当前订单总需求 > 可用成品 + 短期可到货数量 → D8 读取客户 / 渠道优先级、要求日期与订单约束 → 将有限成品分给优先级更高且可以履约的订单 → 其余订单形成延期或最终销售损失 → 实际发运 / 销售结果再反馈 D1

适合的算法

适合使用优先级分配或简单分配规则，按照客户 / 渠道优先级、要求日期、可用库存、近期到货和必要的经济 / 合规约束进行分配。

什么时候重新运行

可用供给小于订单需求；订单变化；客户优先级变化；预计到达时间变化；信用或市场限制变化。
