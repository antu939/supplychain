Supply Chain Decision Architecture

从业务世界，走向供应链决策。

10 类业务数据 → D1–D8 决策 → AI 辅助

先用 10 类业务数据刻画市场、产品、供应、产能、库存、物流、风险与财务， 再把状态转化为 D1–D8 的可执行决策；AI 位于确定性计算之外，负责事件、诊断与场景分析。

项目结构

三个板块，一套完整闭环。

首页先建立供应链的业务世界：10 类数据与网络；随后展示 D1–D8 如何把业务状态转化为决策； 最后进入 AI 事件解析、KPI 异常诊断与 Scenario 分析。

01 · 业务数据与网络

10 类数据共同描述同一个供应链。

数据不是十张彼此独立的表。市场产生需求，产品与 BOM 定义需求结构， 供应商和采购关系提供供给，工厂与物流完成生产和移动，库存连接计划与履约； 风险合规与财务横向约束这些活动。

02 · D1–D8

决策之间不是一条简单的直线。

主链从需求承诺一直到履约，但物料需求、产能、采购 Lead Time、库存和物流之间还存在交叉影响。 点击任一 D 节点，后续进入对应的详细页面。

D1 定卖多少 → D2 拆需要什么；D2 同时向 D3 / D5 传递物料与产能需求，再由采购、生产、库存、物流和履约形成闭环。 8 个节点已保留详情页接口：decisions/d1.html ～ decisions/d8.html。
03 · AI 辅助

把不确定性，放在确定性计算之外。

三个 AI 模块均已接入独立页面：事件解析、KPI 异常诊断与 Scenario 分析；首页作为入口，不改动底层确定性规则与算法。

01

事件解析

把政策、制裁、火灾、停运等外部事件转换为可审核的数据变更。

Event → Entity / State / Logic → Change Set → Human Review → Selective Recalculation
进入 Event 页面
02

KPI 异常诊断

读取确定性计算得到的 KPI 和中间指标，判断偏差可能来自哪个业务环节。

KPI Exception → Root Cause → Query / Compute → Related Decision
进入 KPI 页面
03

Scenario 分析

针对临时 What-if 问题调用 D1–D8 中相关算法，再比较方案并解释结果。

What-if → Run D4 / D5 / D6 / D7 → Compare → Explain
进入 Scenario 页面
